# reply — B. 지원자 응대

지원자에게 무엇을·언제·어떤 문구로 보낼지 정하고, 당근 채팅방까지 가 보고, 테스트 폰 지원자에게만 실제로 보내 보는 기능이에요 (사용자 프로세스 B2·B3).

## 세 단계

| | 하는 일 | 당근에서 | 누구에게 |
|---|---|---|---|
| 계획 (`ReplyPlanner`) | 지원자 상세의 '다음에 앱이 할 일' — 무엇을·언제·어떤 문구로 | 아무것도 안 함 | 모든 지원자 (보여 주기만) |
| 첫 메시지 드라이런 (`FirstMessageDryRun`, 개발용) | 채팅방까지 가서 보낼 문구·발송 전 검사·실제라면 보낼지 | 방까지 가는 칸만 누름 — **입력·전송 없음** | 사람이 버튼을 누른 그 지원자 |
| 실제 발송 시험 (`LiveTurn`·`LiveReply`, 개발용) | 첫 메시지 → 번호 받기 (다시 요청 2번까지) → 마무리 | 입력·전송 | 테스트 폰 지원자 한 명 (`LiveGate`) |

실제 지원자 모두에게 자동으로 보내는 운영은 아직 없어요 — 담당자 확인 뒤예요 (확인사항 29). '앱이 맡은 지원'은 `ReplyScope` 한 곳에서 정해요 (지금은 실제 발송 시험 대상만).

## 채팅방까지 가는 길 (`RoomRoute`)

드라이런과 실제 발송 시험이 같은 길을 써요.

- **대화가 있는 지원자** → 채팅 탭에서 그 사람 방 줄을 눌러요 (이름 + 동네가 맞는 줄이 하나일 때만).
- **아직 채팅 전인 새 지원자** → 채팅 목록에 방이 없어서, 공고에서 그 사람을 직접 눌러 들어가요 (10/20):
  1. 나의 당근 → 공고 → 지원자 보기 → 그 사람 카드
  2. 안 읽은 카드('N')면 지원서를 열고 '채팅하기', 읽은 카드면 카드 아래 '채팅하기'
  3. 지원서에서 '채팅하기'를 못 찾으면 목록으로 돌아와 카드 아래 '채팅하기'
- 앱이 안 읽은 지원서를 열면 당근에선 읽은 카드가 돼요. 그래서 앱 기록에 사유 '앱이 지원서를 엶 (드라이런 · 실제 발송 시험)'을 남겨요. 그래야 당근 가져오기가 '담당자가 봄 → 담당자 응대 중'으로 바꾸지 않아요 (`sync/ApplicantImport.appOpened`).
- 드라이런은 담당자가 이미 본 카드와 안 읽은 메시지가 있는 방은 열지 않아요 (담당자가 대화 중일 수 있고, 열면 상대에게 읽음으로 보여요).
- 누를 칸은 `LiveNav`가 그 사람 것만 찾고, 누르기 직전에 `isSafe`로 한 번 더 봐요. 화면을 옮기는 손은 가져오기와 같은 `sync/DaangnWalker`예요.

## 지키는 것

- 실제로 보내는 코드는 `Live*`뿐이에요. `LiveGate`가 테스트 폰 닉네임 · 시험을 켠 뒤 들어온 지원 · '당근 응대' 켜짐 · 사람이 안 맡음 · 한도(한 사람 4개 · 하루 10개)를 다 봐요. 시험이 끝나면 '끔'으로 돌려요.
- 보내기 전에 입력창에 쓰인 글자를 보낼 문구와 대조해요. 보낸 뒤엔 방에 우리 말풍선으로 보여야 보낸 거예요. 안 보이면 '결과 불명' — 다시 보내지 않고 시험을 꺼요.
- 방에 앱이 보내지 않은 우리 쪽 말이 있으면 사람이 응대 중으로 보고 멈춰요.
- 드라이런은 입력창·전송을 누르지 않아요 (있는지만 봐요).
- 보안 인증·이용 제한 글자가 보이면 바로 멈추고 전체 멈춤을 켜요.

## 폰에서 확인할 때

- 드라이런: 지원자 상세 아래쪽 '당근 첫 메시지 드라이런' (개발용) → '채팅방까지 가서 보낼 문구 확인'. 결과는 '마지막:' 줄과 '드라이런 기록 보기'에 있어요.
- 실제 발송 시험: 지원자 탭의 '실제 발송 시험' 칸 (개발용) — 끔 · 연습 · 실제 발송, 지금 한 번 확인.
- 앱이 본 화면: 폰 안 `files/debug/dryrun_*.xml` · `live_*.xml` (지원서 화면은 `…_application.xml`). 꺼내는 법은 `sync/README.md`에 있어요.
